# Canvas

Редактор цепочки «текст → генератор → результат» на React Flow: сохранение графа через REST и тестовая генерация картинки. Код в `apps/web` (React 19, TypeScript, Vite, `@xyflow/react`, zustand). Бэкенд не трогал.

## Запуск

Node.js 24, npm 11.

```sh
npm ci
npm run dev        # API на :4001
npm run dev:web    # во втором терминале, фронт на :5173
```

Другой адрес API: `VITE_API_URL=http://localhost:4101 npm run dev:web`.

```sh
npm run build:web  # сборка в apps/web/dist
npm run test:web   # юнит-тесты (vitest)
npm run check      # формат, тесты API, сборка и тесты фронта
```

Swagger — http://localhost:4001/docs/. Сброс данных: остановить API и `npm run data:reset`.

## Как устроено

- `api/client.ts` — единственное место с `fetch`. Три шага: собрать запрос (JSON, `If-Match`, `Idempotency-Key`), отправить, разобрать ответ (статус, пустое тело, `ETag`, `Retry-After`). Любой сбой становится `ApiError`. `api/canvas-api.ts` — эндпоинты, каждый описывает только своё.
- `lib/save-queue.ts` — debounce 500 мс и цепочка промисов, так что PUT одного графа идут строго по очереди. Снимок графа строится в момент отправки, поэтому правки во время запроса уйдут следующим PUT. Из ответа берётся только ETag — старый ответ не затрёт свежие правки. На 412 автосохранение останавливается, пользователь выбирает версию сервера или свою.
- `lib/async.ts` — `pollUntil`, `withRetry`, `sleep` с отменой. `lib/idempotency.ts` — пока ответа нет, повтор идёт с тем же ключом.
- `canvas/session.ts` — открытое пространство: граф, ETag, очередь сохранений. `dispose()` отправляет несохранённое и останавливает опрос.
- `canvas/generation-controller.ts` — по кнопке сначала `flush()` очереди, потом запуск генерации и опрос. Если сохранение упало, генерация не стартует. После перезагрузки незавершённые генерации опрашиваются дальше.
- `canvas/generations.ts` — последняя генерация по генератору и по ноде результата. Более старый запуск не перезаписывает новый, картинка идёт только в ту ноду, что была указана при запуске.
- `canvas/connections.ts` — правило связей. `canvas/graph.ts` — сериализация для PUT без служебных полей React Flow.

## onNodesChange при перетаскивании

Самое горячее место: React Flow зовёт `onNodesChange` на каждое движение мыши, обычно с одним изменением позиции.

- `applyNodeChanges` делает один проход по нодам: сдвинутая нода копируется, остальные остаются теми же объектами, так что `memo`-ноды не перерисовываются. Массив плотный, без дырок.
- Нужно ли сохранять — `changes.some(...)`, без промежуточного массива, как было бы с `filter().length`.
- Дальше только перезапуск таймера. Граф сериализуется один раз, когда сработал debounce, а не на каждом кадре.

С проверкой связей похоже: пока тянешь связь, `isValidConnection` вызывается на каждый порт. Индекс (тип ноды по id, занятые входы и выходы) строится за один проход и переиспользуется, пока не поменялись `nodes` или `edges`.

## Что проверял

Юнит-тесты на клиент API, очередь сохранений, правила связей, сериализацию, индекс генераций, retry/poll и ключи. Руками и скриптом Playwright против живого API на 1280 px:

- создание пространства, после перезагрузки открывается оно же с графом и картинками;
- добавление, перемещение и удаление нод вместе со связями, ввод текста не двигает ноду;
- запрещённые связи не создаются;
- быстрый ввод или перетаскивание дают один PUT через 500 мс, медленный PUT не приводит к параллельным запросам;
- 412 при изменении графа снаружи, обе кнопки выхода из конфликта;
- генерация сразу после правки — сначала PUT, потом POST; тестовый отказ и повтор;
- перезагрузка во время генерации, потерянный ответ POST и двойной клик — генерация одна;
- удаление или переподключение ноды результата во время генерации — картинка не попадает в чужую ноду.

## Недоработки

- Связи между нодами тянутся только мышью. С клавиатуры можно добавить готовую цепочку кнопкой «+ Цепочка».
- При конфликте нет слияния, только выбор одной из версий.
- Выбранный сценарий генерации не сохраняется — схема графа не пускает лишние поля.
- При закрытии вкладки с несохранёнными правками браузер только предупреждает.
- Показывается только последняя генерация, истории нет.
- e2e-тесты в репозиторий не добавлял.
