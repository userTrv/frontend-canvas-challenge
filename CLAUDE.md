# Правила для работы в репозитории

## Зависимости

- Ставить только версии, опубликованные не меньше 7 дней назад. npm это проверяет сам (`min-release-age` в `.npmrc`), для остального (GitHub Actions, бинарники) смотреть дату релиза вручную.
- Только известные пакеты из официального реестра: с историей, живым репозиторием и заметным числом скачиваний. Перед добавлением нового пакета проверять точное имя (тайпсквоттинг), автора и нужен ли он вообще. Без git- и URL-зависимостей.
- Настройки защиты в `.npmrc` не ослаблять и не обходить (`--min-release-age=0`, `--allow-git`, `--ignore-scripts=false` и т. п.) без явного согласия владельца. Скрипты установки разрешены только пакетам из `allowScripts` в `package.json`; новый пакет туда — только после того, как посмотрел, что делает его скрипт.
- Установка в CI и при проверках — `npm ci`. `package-lock.json` меняется только вместе с `package.json` и попадает в тот же коммит.
- Нужен npm 11.19.1 или новее (`packageManager` и `devEngines` в `package.json`).
- GitHub Actions подключать по полному SHA коммита с комментарием-тегом (`uses: owner/action@<sha> # vX.Y.Z`), только от известных авторов.

## Секреты и доступы

- Никаких ключей, токенов и паролей в коде, коммитах, логах, PR и комментариях. Локальные настройки — в `.env` по образцу `.env.example`, в `.env.example` только безопасные значения по умолчанию.
- `.env*` (кроме `.env.example`), `*.pem`, `*.key` в `.gitignore`; перед коммитом смотреть `git diff --cached` на предмет случайно попавших секретов.
- Не выводить секреты в консоль (`echo`, `set -x`, `env`, `cat` ключа), не передавать их аргументами командной строки, не отправлять во внешние сервисы.
- В workflow права по минимуму (`permissions: contents: read`, дописывать только нужное), `persist-credentials: false` у checkout, секреты — только через `env:` шага.
- Нашёлся утёкший секрет — сразу сообщить владельцу: его надо отозвать и перевыпустить, одного удаления из истории мало.
